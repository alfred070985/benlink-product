# benlink-product 项目说明

本来生活（Benlai）分销定价项目。核心资产是**两个货盘的定价交付物**、采集与校验脚本、源数据快照和业务口径文档。私有仓库，含敏感价格数据（成本/供货价/协议价）。

## 这个项目在做什么

一句话：**给本来生活的分销商品自动定价，同时把技术公司能卖的完整供应链（三个货源）整合成一张可经营的聚合货盘。**

### 两个货盘（业务顶层框架，不可混）

```
货盘一 = 本来货盘（本来定制）
  本来分销底盘（四站可售 + 选品规则）
    → ERP成本 × 分档加价（直发 2/5/8%、仓发 5/12/24%）
    → 市场价参照：天镜智价（主）+ 京东VOP相似采信 + 猫超券后价折算（补）
  服务对象：只供本来生活体系。周频滚动更新。

货盘二 = 技术公司全货盘（自营生意）
  货盘一原样搬入（本网=内部产出，保留内部逻辑）
  + 京东VOP（外部引入，协议价=进货成本，直发档 2/5/8%）
  + 猫超（外部引入，SKU供货价=进货成本，直发档 2/5/8%）
  三表并集、每货源一行、同品组 group_id 关联、空间率≥10% 过滤。
```

关键认知：猫超和京东 VOP 在两个货盘里**角色不同**——对货盘一是"定价的镜子"（市场价参照），对货盘二是"货源"（进货成本）。

### 周频定价/ —— 每周跑的完整结构

```
周频定价/
├── 交付物/                     ← 唯一对外出口，按 ISO 周归档（最重要）
│   └── 2026-Wxx/
│       ├── 01_货盘一_本来定制/        上层交付物①：分销标准池定价 xlsx
│       ├── 02_货盘二_技术公司全货盘/  上层交付物②：聚合表 csv + 链路 HTML
│       └── 03_货盘底表/               下层按货源拆开的五个底
│           ├── 1_本来生活货盘/   池子、成本明细、商品信息、选品v2+剔除
│           ├── 2_京东VOP货盘/    VOP底表csv、本网×京东相似匹配
│           ├── 3_天镜智价货盘/   价格历史全量、人工核实同品映射
│           ├── 4_猫超货盘/       宽表、list、详情、SKU、价格
│           └── 5_跨源对齐/       条码对齐、三方向匹配、任务1折算
├── pricing_output/    ← 货盘一工作区（本网采集+选品+定价脚本）
├── allpool_output/    ← 货盘二工作区（对齐+聚合脚本，含 latest.py 路径解析）
├── supply_pull/       ← 外部货源采集区（京东VOP + 猫超TOP接口，含看门狗）
├── weekly_pipeline.py ← 周频自动化三阶段编排（周日/夜间/周一）
└── weekly_work/       ← 哨兵与日志（运行期生成，不入库）
```

**为什么这样分区**：对外交付（交付物）、内部厨房（三个工作区）、自动化编排物理分开；成品产出后从工作区移入当周交付物，一处一份。`latest.py` 全仓按文件名日期解析路径，目录再调整也不破坏复跑。

## 每周更新流程（已由 weekly_pipeline.py 自动化）

| 阶段 | 时间 | 内容 |
|---|---|---|
| `sunday` | 周日 20:00 | 京东VOP全量刷新 + 猫超list全量 + **新品详情增量回查**（不每周重建81万SKU） |
| `price` | 周日夜间后台 | 猫超全量价格刷新（约10h，断点续跑）——价格是唯一没有增量信号的数据 |
| `monday` | 周一 06:30 | 本网池重筛5步 → 选品v2 → 货盘一定价 → 猫超宽表 → 货盘二 → **自动归档**进交付物/当周W文件夹 → 登记清单 → 提交推送 |

天镜智价另有每日 9:00 的日频任务。阶段间用哨兵文件衔接；价格没跑完不阻塞主链（回退上周价格）。`WEEKLY_DRYRUN=1` 可空跑验证链路。

- 路径解析统一走 `周频定价/allpool_output/latest.py`（环境变量 > 全仓文件名日期最新），脚本均支持环境变量覆盖（R1 自包含）
